# ADR 0006 — Inventory ledger and reviewed stock control

Date: 2026-09-23. Implements L5. Business-specific confirmations remain in ignored local intake records; real opening quantities, values and operational acceptance remain pending.

Stock is stored by branch, variant and condition (`sellable`, `damaged`, `quarantined`). Quantities are base-unit quantities with six decimal places. Pack conversion is snapshotted as catalog metadata; entering pack quantities does not automatically convert them. Once a variant has stock documents, movements or reservations, its unit, conversion and fractional policy cannot change. Create a new variant instead.

Balances hold quantity, value and reserved quantity. Sellable availability is sellable quantity minus active reservations; damaged and quarantined balances are separate. Additions accept explicit cost per base unit. Deductions consume moving weighted-average value, rounded half-up to six places, with the final deduction consuming the remaining value exactly. This is the technical precision policy; physical opening values and exceptional damage/landed-cost treatment still require business acceptance.

`stock_adjustments` and its items are the common document aggregate for opening stock, adjustments, counts and reconciliation corrections. This avoids separate posting logic for the four workflows. Each document retains its normalized import/input manifest, source reference, content checksum, reason, optional original-document link, catalog snapshots, prior balance/version and ledger totals. Opening dates record the cutover source date; movements always use their actual posting timestamp. Ordinary backdating is unavailable. Opening is allowed only before a variant's first branch movement.

Drafts are versioned. Their author can edit and refresh balance snapshots; another authorized user must review and post. The approver confirms their own password in their own current session. Authorization, author eligibility, document version, stock snapshots, immutable movements, balances, document number, audit, outbox and idempotency response are checked or written in one transaction. Approval is consumed immediately by posting; no reusable approval token exists. Passwords are excluded from idempotency hashes and persisted payloads. Posted and cancelled documents cannot be edited, and runtime privileges prohibit ledger update/delete/truncate.

All stock writers acquire branch/variant advisory locks in sorted order, then lock the three condition rows in a fixed order. This covers absent balances and lets the same boundary protect future receiving, checkout and transfers. Multi-item callers must lock the complete scope before applying any movement. Bounded transaction retries handle serialization/deadlock errors. Reservations use the same locks, require availability and have immutable allocation/release events. A later transfer module can release and deduct in the same transaction; L5 exposes allocation and full release only.

A count draft freezes its complete branch/variant scope before physical counting. Other movements and reservation transitions are blocked until posting or explicit cancellation. Counts do not automatically expire or silently unfreeze. The author enters counted totals by editing the saved draft; the server calculates deltas from the frozen baseline. Stock in other variants and branches remains available.

Reconciliation reads balances, movement sums and active reservations in one SQL snapshot. Ordinary writes fail on a mismatch. A dedicated reconciliation correction snapshots the discrepancy and, after independent review, restores the cached quantity/value/reserved fields from unchanged source history. It creates no fictional stock movement because physical stock has not changed. The correction document, its before/after report, audit and outbox provide the repair evidence. Physical differences use a count or linked adjustment, not this repair. Invalid source history must be investigated by the maintainer.

Opening CSV imports validate all rows before creating a draft, retain a normalized manifest, reject unknown/duplicate/invalid rows, and support at most 100 lines within the API body limit. The document screen and CSV reconciliation report show before/change/after quantity and value. Read endpoints and exports enforce branch membership and inventory permission. The local outbox stores typed inventory event references; cloud delivery remains disabled.
